# Within

[Открыть Within](https://within-roan.vercel.app)

Личный блокнот и коллекция целей. Русский интерфейс, тёмная тема, React + Vite + TypeScript, React Router, lucide-react. Пользователь сам отмечает выполнение: без сроков, планов, статистики и игровых механик.

## Быстрый запуск без аккаунта

Нужен Node.js 24 (для установленной версии Vitest 5).

```sh
npm ci
npm run dev
```

Откройте http://localhost:5173. Если обе переменные Supabase отсутствуют или одна из них пустая, открывается демо с примерами. Данные сохраняются в localStorage этого браузера. Формы входа и регистрации не показываются, пароли не запрашиваются. Можно сразу создавать цели и записи, менять статус, сохранять воспоминания, пользоваться корзиной и экспортом.

```sh
npm test
npm run build
```

`dist/` — готовая сборка для статического хостинга.

## Подключение Supabase — пошагово

### 1. Создание проекта

Создайте проект на https://supabase.com/dashboard. Дождитесь готовности базы. Миграции рассчитаны на PostgreSQL 15 или новее (используется `ON DELETE SET NULL (goal_id)` для составного внешнего ключа).

### 2. Project URL и публичный ключ

Откройте **Project Settings → API**. Скопируйте **Project URL** и **anon / publishable key**. Допустим только публичный ключ. Серверные секретные ключи для этого приложения не нужны и в клиент не вставляются.

### 3. Переменные окружения

Скопируйте `.env.example` в `.env.local`:

```dotenv
VITE_SUPABASE_URL=https://your-project.supabase.co
VITE_SUPABASE_ANON_KEY=your-public-key
VITE_ENABLE_GOOGLE=false
```

`.env.local` исключён из Git. После изменения переменных перезапустите Vite. Они попадают в клиентскую сборку, поэтому содержат только публичные значения. Без двух заполненных значений приложение остаётся в демо-режиме.

### 4. Применение миграций

В Supabase **SQL Editor** выполните целиком файлы по порядку:

1. `supabase/migrations/001_private.sql`
2. `supabase/migrations/002_public_storage.sql`
3. `supabase/migrations/003_existing_profiles.sql` — профили для аккаунтов, созданных до миграций.

Либо через Supabase CLI:

```sh
supabase login
supabase link --project-ref YOUR_PROJECT_REF
supabase db push
```

Миграции создают profiles, goals, notes, memories, RLS, триггер создания профиля, обновление updated_at, RPC конвертации и очистки корзины, публичные функции и два приватных бакета. Не запускайте эти миграции повторно вручную поверх уже созданных таблиц.

Если расширение `pg_cron` уже установлено, вторая миграция создаст ежедневную очистку старой корзины. Если его нет, приложение вызывает `purge_my_trash()` при каждом запуске. Cron не обязателен. Через SQL Editor ролью владельца можно проверить задание в `cron.job`.

### 5. Auth → URL Configuration

Для локальной разработки:

- **Site URL**: `http://localhost:5173`
- **Redirect URLs**: `http://localhost:5173/auth/callback` и `http://localhost:5173/reset-password`
- При необходимости добавьте также `http://localhost:5173`.

Для опубликованного приложения добавьте точные адреса своего домена:

- `https://your-domain.vercel.app/auth/callback`
- `https://your-domain.vercel.app/reset-password`
- `https://your-domain.vercel.app`

При публикации Site URL должен стать адресом опубликованного приложения. Восстановление ведёт на отдельную страницу `/reset-password`, которая принимает recovery-сессию. Обычный переход на эту страницу без recovery-ссылки не открывает форму нового пароля.

### 6. Подтверждение email и письма

В **Authentication → Providers → Email** настройте подтверждение email. При включённом подтверждении регистрация покажет «Проверь почту»; профиль создаст триггер auth.users. Переход по ссылке подтверждения обработает Supabase SDK, затем откроется приветствие.

В **Authentication → Email Templates** проверьте Confirm signup и Reset password. Для используемого здесь стандартного implicit-потока оставьте ссылку `{{ .ConfirmationURL }}`. Не заменяйте её собственной ссылкой без параметров токена. Для реальных писем настройте свой SMTP и ограничения отправки проекта.

Google необязателен: включите провайдера Google в Supabase, настройте OAuth callback из панели Supabase и задайте `VITE_ENABLE_GOOGLE=true`. Кнопка скрыта при любом другом значении.

### 7. Локальный запуск

```sh
npm ci
npm run dev
```

Создайте тестовый аккаунт. После подтверждения email выберите пустое пространство или три обычные цели. Примеры можно удалить. Приватность включена по умолчанию: выполнение не публикует цель автоматически.

### 8. Публикация на Vercel или Netlify

Загрузите исходники в свой Git-репозиторий и подключите его к хостингу.

- Framework: **Vite**.
- Build command: `npm run build`.
- Output directory: `dist`.
- Node.js: 24.
- Добавьте три переменные окружения из `.env.example` в настройки хостинга.

`vercel.json` содержит SPA rewrite на index.html. `netlify.toml` содержит redirect `/* → /index.html` со статусом 200. Это необходимо для прямого открытия `/notes/...`, `/u/...` и `/reset-password`. В качестве альтернативы можно загрузить `dist` на Netlify, сохранив SPA-правило в настройках проекта.

В этой сессии приложение не публиковалось на внешнем хостинге: подготовлен исходный код и локальный просмотр.

### 9. Адреса после публикации

Обновите **Site URL**, **Redirect URLs** (корень, `/auth/callback`, `/reset-password`) в Supabase. Пересоберите приложение после добавления переменных на хостинге. Если домен меняется, поменяйте эти адреса снова. Ссылки на публичный профиль используют текущий origin приложения. Для production вместо localhost используйте HTTPS.

## Архитектура и поведение данных

- `src/domain.ts` — типы и чистая логика целей, поиска, публикации.
- `src/repository.ts` — интерфейс Repository и localStorage-реализация.
- `src/supabase.ts` — реализация Supabase; компоненты вызывают один и тот же интерфейс.
- `src/drafts.ts` — последовательная очередь сохранения записей и защита перехода.
- `src/App.tsx` — маршруты, экраны и доступные диалоги; `src/main.tsx` — точка входа.
- `src/style.css` — токены, desktop/mobile, safe-area и reduced-motion.

Записи хранятся в Markdown. Сырой HTML не исполняется. В предпросмотре ссылки только http, https, mailto; открываются с `noopener noreferrer` в новой вкладке. Автосохранение запускается примерно через 800 мс. Черновик хранится в памяти и localStorage по id записи и пользователя. Сохранения одной записи идут последовательно, более старый снимок не заменяет более новый. Переход ожидает сохранение; при сбое показывает предупреждение. Закрытие вкладки с несохранённым текстом вызывает beforeunload. После сбоя повтор выполняется через 5 секунд, при возвращении сети или кнопкой «Повторить».

Перевод записи в цель использует `goal_from_note`: блокировка строки и проверка владельца предотвращают дубликаты. Исходная запись остаётся. Сохранение текста обновляет только title/body, не затирает закрепление и связь.

`completed_on` — календарная дата, отображается без пересчёта часового пояса. Остальные даты — ISO/timestamptz UTC, отображаются локально. Будущая дата выполнения запрещена на клиенте и в базе. При отмене выполнения воспоминание остаётся, но скрывается из «Моего пути». На одну цель — одно воспоминание.

Публичные функции возвращают только имя и разрешённые выполненные цели (название, категория, дата, разрешённый текст воспоминания). В них нет id, email, описаний, изображений или блокнота. Выключенный и несуществующий профили возвращают пустые массивы. Слаг случайный (32 символа), сохраняется при выключении. В демо публичная ссылка работает только в текущем браузере; другим людям её данные недоступны.

Бакеты covers и avatars приватные, MIME JPEG/PNG/WebP, до 5 МБ. Пути `{user_id}/{uuid}.{ext}`; чтение — signed URL на 5 минут, интерфейс обновляет URL каждые 4 минуты. В демо изображения сохраняются как data URL в localStorage; его объём ограничен браузером. При переполнении показывается ошибка сохранения. Файлы в Storage после удаления записи из базы могут оставаться в приватном бакете: автоматическое удаление непривязанных файлов не реализовано.

Мягкое удаление хранит deleted_at. Восстановление цели сохраняет связи и воспоминание; окончательное удаление обнуляет notes.goal_id и удаляет память через FK. Экспорт содержит все не находящиеся в корзине цели, записи и связанные воспоминания; не содержит паролей или токенов. Несохранённый текст редактора сначала сохраняется перед переходом к экспорту.

### Ограничение писем при проверке восстановления

10.10.2026 журнал настоящего Supabase показал HTTP 429 на /auth/v1/recover. Форма теперь различает лимит писем, лимит запросов и сетевую ошибку; проверено тестами. Встроенная почта Supabase ограничена двумя письмами в час на проект. Используйте уже полученное письмо либо повторите позже. Для обычной регистрации пользователей подключите собственный SMTP в Auth → Emails; без него встроенная почта также ограничивает адресатов командой проекта. Настройка SMTP пока не выполнена.


### Проверка публичной страницы на настоящей базе — 10.10.2026

Создан отдельный вымышленный профиль без email и пароля. В браузере без входа проверено: показываются только имя, опубликованная выполненная цель и разрешённое воспоминание; скрытая цель, описание, обложка и блокнот отсутствуют. ### Проверка загрузки изображения — 10.10.2026

Пользователь загрузил JPEG через форму цели. В настоящем Storage подтверждён файл image/jpeg размером 801550 байт. После перезагрузки приложения цель IV и её обложка загрузились из Supabase. DOM-проверка подтвердила загрузку изображений в карточке и панели (naturalWidth 768) через /storage/v1/object/sign/covers/. Пользовательская цель сохранена. Эта проверка подтверждает загрузку обложки и signed URL; загрузка аватара и истечение подписанной ссылки отдельно НЕ проверены.


### Повторное открытие изображений

Ссылки изображений кэшируются в памяти отдельно для экземпляра репозитория (аккаунта), одинаковые одновременные запросы объединяются. Кэш действует 240 секунд при сроке signed URL 300 секунд. В браузере проверен переход Цели → Блокнот → Цели: обе обложки загружены, ссылки остались теми же. Тестами проверены объединение запросов, обновление по истечении, изоляция источников и повтор после ошибки. Первый запрос после перезагрузки по-прежнему требует сети.

### Режим письма и история записей
Кнопка «Сосредоточиться» скрывает навигацию и список записей; «Вернуться» или Esc возвращает обычный вид. История хранит последние 100 предыдущих версий названия и текста в localStorage отдельно по пользователю и записи, только после успешного сохранения. История не синхронизируется между устройствами и исчезает при очистке данных браузера. Восстановление проходит через автосохранение; заменённый текст сохраняется в истории. 30 тестов и сборка пройдены; визуальная проверка новой версии в браузере не выполнена.
